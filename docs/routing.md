# Правила роутинга

Маршруты организуются по функциональным доменам. Каждый домен владеет своими
HTML-страницами, API и именами endpoint-ов. Общий реестр находится в
`app/routes/__init__.py`.

## Структура

```text
app/routes/
├── auth/       # вход, OAuth callback, выход
├── practice/   # лента, карточки, ответы, пропуски и жалобы
├── profile/    # профиль, настройки и пользовательский фон
├── admin/      # административный API
├── legacy.py   # временная совместимость со старыми URL
└── system.py   # технические маршруты приложения
```

В домене файл `pages.py` возвращает HTML, а `api.py` обслуживает программные
запросы. Blueprint экспортируется из `__init__.py`. При росте домена новые
обработчики добавляются в его пакет, а не в общий файл.

## URL и методы

- HTML-страницы используют короткие пользовательские URL: `/`, `/filters`,
  `/profile`, `/auth`.
- API имеет версионированный префикс `/api/v1`.
- Ресурсы именуются существительными во множественном числе: `attempts`,
  `words`.
- Действие выражается HTTP-методом: `POST` создаёт, `PATCH` частично изменяет,
  `DELETE` удаляет.
- Фильтры страницы передаются query-параметрами. Для ленты используются
  `task`, `category` и `mode`; отдельные страницы под каждый фильтр не создаются.
- Имена endpoint-ов имеют вид `<domain>.<action>` или
  `<domain>_api.<action>`.

## Обработчики

HTTP-обработчик отвечает только за:

1. чтение и базовую проверку входных данных;
2. вызов функции из `app/services`;
3. преобразование результата в HTML, JSON или redirect.

Запросы, объединяющие несколько моделей, изменение состояния и внешние OAuth
запросы должны находиться в сервисах. Проверки доступа размещаются в
`app/security`. Модуль маршрута не должен импортироваться из сервиса.

## Фронтенд

- URL для JavaScript формируются через `url_for` в шаблоне и передаются через
  `window.routeConfig`.
- Новые абсолютные строки вида `fetch('/some_route')` не допускаются.
- Параметры пути формируются на сервере; query-параметры на клиенте добавляются
  через `URLSearchParams` или `encodeURIComponent`.

## Ошибки API

Ошибочный ответ содержит стабильный машинный код и понятное сообщение:

```json
{
  "error": "word_not_found",
  "message": "Word not found"
}
```

HTTP-статус отражает тип ошибки. UI не должен определять ошибку по тексту
`message`; для ветвления используется `error`.

## Совместимость

Старые адреса собраны только в `app/routes/legacy.py` и не используются новым
кодом. GET-маршруты перенаправляются на канонические URL кодом `308`. Для POST
оставлены адаптеры, потому что redirect запроса с телом поддерживается клиентами
неодинаково.

Совместимый маршрут можно удалить после того, как в логах за согласованный
период нет обращений к нему. Новые aliases вне `legacy.py` не добавляются.

## Проверки перед merge

- Каждый новый маршрут присутствует в тесте карты URL.
- Для изменения состояния проверяются допустимый метод, валидация, права и
  основные статусы ошибок.
- В шаблонах и исходном JavaScript отсутствуют ссылки на legacy URL.
- `python -m unittest discover -v` проходит полностью.
